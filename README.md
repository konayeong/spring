# Spring Boot MVC 결산과제
## [NHN Mart 고객센터]
## 📖 프로젝트 개요
NHN Mart에서 발생하는 고객 문의를 처리하기 위한  
고객/CS 담당자용 웹 애플리케이션이다.

- 고객: 문의 등록 및 조회
- CS 담당자: 미답변 문의에 대한 답변 처리

---

## 🧱 기술 스택
- Java 21
- Spring Boot (Spring MVC)
- JDBC (**DBCP** or HikariCP)
- Thymeleaf
- MySQL
- JUnit

---

## 👤 주요 기능

### 고객 기능

#### 🔐 로그인 / 로그아웃
- 세션(HttpSession) 기반 인증 처리
- 로그인 실패 시 예외 발생

#### 📋 내 문의 목록 조회
- 본인이 작성한 문의 목록 조회
- 최신순 정렬 (최근 작성이 상단)
- 답변 여부 확인 가능
- pagination 없음

#### 🔍 문의 상세 조회
- 답변 전
    - 제목, 분류, 본문, 답변 여부 표시
- 답변 후
    - 답변 내용
    - 답변 일시
    - CS 담당자 정보

#### ✏️ 문의 등록
- 입력 항목
    - 제목 (2 ~ 200자)
    - 본문 (0 ~ 40,000자)
    - 분류
    - 첨부파일 (이미지 N개)

- 유효성 검증
    - 제목/본문 null 체크
    - 파일 타입 제한 (gif, jpg, jpeg, png)

- 처리 흐름
    - 저장 후 목록 페이지로 리다이렉트
    - 최신 글이 상단에 노출

#### 🔎 문의 검색
- 분류 기준 필터링

---

### CS 담당자 기능

#### 🔐 로그인 / 로그아웃

#### 📋 미답변 문의 목록 조회
- 답변이 없는 문의만 조회

- 유효성 검증
    - 답변 (1 ~ 40,000자)

### JSESSIONID
> 서버(톰캣)가 클라이언트(브라우저)를 식별하기 위해 발급하는 세션 ID
- 흐름
  - 클라이언트 최초 요청
  - 서버가 세션 생성
  - 서버가 응답에 쿠키로 내려줌
  - 이후 요청마다 브라우저가 자동으로 보냄
  - 서버는 이 값으로 같은 사용자인지 구분
- 핵심 역할
  - 로그인 상태 유지
  - 사용자별 데이터 저장(session.setAttribute)
  - 서버에서 상태 관리
- 세션 유지 방식 2가지
  - 쿠키 방식 (기본)
    - Cookie: JSESSIONID=ABC123
  - URL Rewriting 방식 (fallback)
    - 쿠키 못 쓸때만 사용
    - URL에 세션 노출 
- 문제 상황
  - 쿠키 삭제 후 로그인 시 URL Rewriting 방식으로 작동하면서 error page 반환
  - 해결
    - `server.servlet.session.tracking-modes=cookie`
    - URL 방식 쓰지 말고, 무조건 쿠키만 쓰도록 설정
